# iPhone 17 Pro warm re-capture campaign — 2026-07-13

Closes the cold-only methodology issue (fairness-rules §2): every cell is one
`--runs 4` process — **cold** = run 1 (fresh process, weights on disk),
**warm** = median of in-process runs 2-4 (the vendor-model-card convention).
Driver: `scripts/bench_warm_matrix_iphone.sh` (device-jsonl copy-back +
`initialThermalState == nominal` gate per run). Device: iPhone 17 Pro
(iPhone18,1), iOS 27.0 (24A5355q), Release build, plugged, Auto-Lock never.

`device-jsonl/` holds the raw per-run JSON exactly as the app wrote it.
`summary.md` is generated by the driver's `report` subcommand.

## Scope

Re-captured (bundles present on device): Qwen3-0.6B / 1.7B / 4B and
Gemma-4-E2B x {MLX, LiteRT-LM} + Core AI 4B (ANE + GPU, June-compiled bundles).

NOT re-captured — and why:
- **Core AI 0.6B / 1.7B**: bundles cannot be re-assembled — `coreai-build`
  aborts on the current macOS 27 beta on every IR/platform/toolchain
  combination (`methodology/coreai-build-regression-2026-07.md`). June cold
  rows stay published with a "warm pending" flag.
- **CoreML-LLM 0.6B**: the stateful-chunks bundle is no longer on the device
  or the Mac; re-conversion is a separate work item.
- The 9 other models of the 11-model cross-framework table: Core AI bundles
  were removed from the device (storage) and can't be rebuilt (same toolchain
  regression). Their June cold table stands, labelled cold.

## Session notes (read before citing)

- **MLX Qwen3-0.6B session variance**: same binary + pins read 126-133 in June
  and 159-180 across today's sessions — cross-session ratios are invalid; see
  `../2026-07-13-mlx-variance/README.md`. All ratios cited from this campaign
  are within-session.
- **Qwen3-4B MLX ran twice**; the second pass (files `*T08-16-*Z`) started
  ~100 s after the first and reads 23.9→22.2 tok/s monotonically declining =
  thermal contamination the 4-level `nominal` gate cannot see. It is EXCLUDED
  from the import (kept here for audit). The first pass (28.1 cold / 27.9 warm)
  matches the June cold 27.3 and is the published row. Lesson: ≥3B cells need
  ≥240 s cooldown, not 100 s.
- **LiteRT-LM Qwen3-0.6B** is the morning tier-1 session (files `*T06-*Z`,
  same protocol/build/device): 121.0 cold / 120.4 warm, all runs nominal.
- **LiteRT-LM teardown hang**: breaking the stream at the 128-token budget
  leaves the engine generating; the next in-process run blocks ~10 min on
  `callback_thread_pool` DEADLINE_EXCEEDED before recovering. Runs complete
  and the data is valid — litert cells just take ~10 min per run. The driver's
  `gtimeout` guard exists because of this (upstream: no cancel propagation in
  the 0.13 preview streaming API).
